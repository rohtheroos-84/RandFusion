\begin{abstract}
Cryptographic systems depend on high quality randomness for tokens, nonces, and identifiers. Traditional randomness assessment workflows rely on independent pass fail decisions from statistical tests and often provide fragmented evidence. This paper presents RandFusion, a machine learning framework that aggregates multiple statistical randomness indicators into a single decision with confidence and explanation. We generate a balanced dataset of one thousand token batches from strong and weak generators, extract thirty two features using a NIST test subset and complementary entropy, autocorrelation, run length, and compression metrics, and train logistic regression, random forest, XGBoost, and stacking models. On a held out test set, random forest reaches 0.8067 accuracy, 0.8380 F1, and 0.7959 ROC AUC, outperforming entropy threshold and matching or exceeding NIST pass fail baselines. Explainability is provided using global feature importance and local SHAP style analysis. Results show strong detection for bias and repetition failures but persistent blind spots for XOR collapse and predictable seed generators. The study demonstrates that learned fusion improves decision consistency for statistical evidence, while also clarifying the limits of statistical testing as a proxy for cryptographic security.
\end{abstract}

\section{Introduction}
Randomness quality is a first order requirement for secure software systems. Session identifiers, API secrets, one time tokens, anti replay values, and key material all inherit risk from weaknesses in random number generation. If the underlying source is biased, state constrained, or predictably seeded, downstream protocols can fail even when encryption primitives are correctly implemented. For that reason, security guidance in standards and operations documents consistently emphasizes robust randomness engineering and systematic validation \cite{b1}, \cite{b2}, \cite{b7}.

The common validation workflow remains test centric: analysts run statistical batteries, inspect p values, and apply fixed cutoffs. This process is useful and often necessary, but in practice it faces three limitations. First, independent pass fail checks do not explicitly model cross test interactions. Second, hard thresholds remove information about degree and direction of deviation. Third, analysts must manually interpret borderline cases, making decisions less repeatable across teams and environments. Historical RNG literature and test battery frameworks already acknowledged these interpretive challenges, especially when generators pass most tests but still exhibit exploitable structure \cite{b4}, \cite{b10}.

This work studies randomness evaluation as a supervised classification problem. Instead of treating each statistical test as a final gate, we treat tests as feature generators and learn a decision boundary over fused evidence. We implement this idea in RandFusion, a complete framework that includes synthetic data generation, statistical feature extraction, model training, baseline comparison, explainability, and stress testing.

The token batch setting introduces a practical difference from classical long-stream RNG analysis. In production systems, analysts often inspect finite collections of short tokens rather than arbitrarily long stationary sequences. This finite sample regime increases variance in p values and can produce unstable threshold decisions. By learning over joint statistical patterns, RandFusion seeks to stabilize this decision process while retaining compatibility with established statistical tests \cite{b1}, \cite{b4}.

From a research perspective, this study contributes not only a model but a complete reproducible pipeline with data generation, feature extraction, training, baseline comparison, explainability artifacts, stress tests, and report outputs. The project is designed to be auditable, extensible, and suitable for security engineering studies where both performance and interpretability are required.

\subsection{Contributions}
This paper contributes a full end to end framework for machine learning based fusion of classical randomness tests, a controlled balanced dataset of one thousand labeled batches spanning two strong and eight weak families, and a thirty two feature representation that combines NIST SP 800-22 subset outputs with entropy, run, autocorrelation, and compression metrics. It further benchmarks logistic regression, random forest, XGBoost, and stacking against entropy threshold and NIST pass fail baselines, and complements quantitative results with explanation outputs through feature importance and SHAP style attributions. Finally, it reports out of distribution stress behavior and generator level error modes to clarify where statistical fusion succeeds and where security limitations remain.

\section{Background and Related Work}
\subsection{Classical Randomness Assessment}
NIST SP 800-22 established one of the most widely used statistical frameworks for evaluating random and pseudorandom bit sequences in security applications \cite{b1}. In parallel, RFC 4086 documented operational randomness requirements and entropy management principles for secure systems \cite{b2}. Foundational cryptography references similarly emphasize that randomness quality directly impacts protocol and key security \cite{b3}.

Beyond NIST, TestU01 and Diehard style batteries reinforced empirical validation as a practical requirement in RNG engineering \cite{b4}, \cite{b10}. Together, these frameworks shaped modern RNG evaluation practice, but they also reveal an analyst burden when independent test outcomes disagree or remain near thresholds.

A critical point from this line of work is that passing statistical batteries does not prove cryptographic strength. Statistical tests can reject clear non randomness, but they cannot fully characterize adversarial predictability, internal state exposure, or flawed seeding logic. This distinction motivates hybrid approaches that combine statistical evidence with model based or structural analyses.

\subsection{Machine Learning and Explainable Evaluation}
Prior studies have explored machine learning for randomness and sequence quality assessment \cite{b5}, \cite{b6}. Recent work continues this direction in security oriented environments such as IoT where resource constraints and deployment heterogeneity complicate static validation assumptions \cite{b11}. While these studies are encouraging, many reported systems either target narrow generator families or provide limited explanation depth for analyst workflows.

Explainable model interpretation frameworks, particularly additive feature attribution approaches such as SHAP, provide a practical bridge between performance and auditability \cite{b8}. For randomness analysis, attribution can reveal whether decisions are driven by expected indicators (for example entropy or run behavior) or by unstable artifacts.

\subsection{Recent Journal Developments 2021 to 2026}
Recent journal literature has deepened understanding of test quality itself. Studies on NIST test interdependence and error analysis show that nominally separate tests can exhibit correlated behavior, which has direct implications for threshold based decision rules \cite{b12}, \cite{b13}.

In parallel, entropy source research has expanded across integrated digital circuits and cosmic radiation based entropy acquisition \cite{b14}, \cite{b15}. These developments matter for software side evaluation because source quality and post processing architecture shape downstream statistical behavior.

Another strand focuses on strengthening validation itself, including algorithmic information theoretic approaches to test battery construction and updated random source analyses in contemporary implementations \cite{b18}, \cite{b19}, \cite{b20}. This trend supports the premise that richer evidence aggregation is increasingly necessary.

Together, these works motivate a framework like RandFusion: preserve trusted statistical indicators, but aggregate them through a learned decision layer and analyze behavior under realistic stress conditions.

\subsection{Formal Problem Definition}
Each sample is a token batch $b_i$ containing $N$ tokens of fixed length $L$ bits. The feature extractor computes
\begin{equation}
\mathbf{x}_i = [f_1(b_i), f_2(b_i), \ldots, f_{32}(b_i)], \;\; \mathbf{x}_i \in \mathbb{R}^{32}.
\end{equation}

The target is binary:
\begin{equation}
y_i \in \{0,1\}, \quad 0=\text{weak}, \; 1=\text{strong}.
\end{equation}

For stacking, base model probabilities are concatenated as meta features:
\begin{equation}
\mathbf{p}_i=[p_{LR},p_{RF},p_{XGB}],
\end{equation}
and the meta classifier predicts
\begin{equation}
\hat{y}_i = \mathbb{I}\left(\sigma(\mathbf{w}^{T}\mathbf{p}_i + b) \geq \tau\right).
\end{equation}

\subsection{Data Generation Protocol}
To make class semantics explicit, RandFusion uses controlled synthetic generation with reproducible seeding and metadata tracking. Strong sources are \texttt{secrets} and \texttt{os.urandom}, both tied to high quality operating system entropy. Weak families are selected to represent practical failure types seen in software systems: low state LCGs, biased outputs, repeated seed blocks, predictable seeding practices, and XOR collapse constructions.

The default configuration uses 1000 samples (500 strong, 500 weak), each sample comprising 1000 tokens of 128 bits. This creates a manageable but sufficiently large training corpus for feature based learning while preserving reproducibility and auditability. The weak class intentionally includes both obvious failures (for example strong bias) and more subtle constructions (for example predictable seed and XOR collapse) so that model behavior can be evaluated across a graded difficulty spectrum.

\subsection{Feature Engineering}
The thirty two dimensional vector blends statistical p values, test statistics, and structural indicators.

\textbf{NIST subset:} Frequency, Block Frequency, Runs, Longest Run, Serial, Approximate Entropy, and Cumulative Sums (forward and backward), including key p values and statistics \cite{b1}.

\textbf{Information and structure metrics:} Shannon entropy, min entropy, maximum observed probability, run mean, run deviation, maximum run, run count, autocorrelation at lags 1, 2, 4, 8, and 16, and compression ratio.

Representative definitions used in implementation include
\begin{equation}
H_{\text{Shannon}} = -\sum_{j} p_j \log_2 p_j,
\end{equation}
\begin{equation}
H_{\text{min}} = -\log_2\left(\max_j p_j\right),
\end{equation}
and lag-$k$ autocorrelation on mapped sequence $x_t \in \{-1,+1\}$:
\begin{equation}
\rho_k = \frac{1}{T-k}\sum_{t=1}^{T-k}x_t x_{t+k}.
\end{equation}

This combination aims to capture both distributional balance and temporal dependency patterns that can reveal non random structure.

From a practical perspective, these features were chosen to maintain a bridge with established test practice \cite{b1} while still exposing richer structure for machine learning. The design explicitly avoids opaque latent embeddings at this stage so that feature level explanation remains possible for auditors.

\subsection{Learning Stack}
RandFusion trains Logistic Regression, Random Forest, XGBoost, and a stacking ensemble. Logistic Regression provides a linear reference and calibrated baseline under scaling. Random Forest and XGBoost model non linear interactions among features. The stacking layer is intended to combine complementary strengths through probability level fusion.

For operational interpretability, we retain two explicit baselines: an entropy threshold decision on Shannon entropy, and a NIST pass fail rule that marks a sample weak when any selected p value crosses the significance threshold. These baselines provide a transparent anchor for interpreting ML gains in real deployment terms.

\subsection{Explainability Design}
Interpretability is integrated as a first class objective rather than an afterthought. We produce global feature rankings from tree models and local SHAP style attributions for per sample decisions. These explanations are used to inspect whether model confidence aligns with expected statistical behavior and to diagnose hard false positive or false negative regimes \cite{b8}.

\section{Experimental Setup}
\subsection{Implementation Environment}
The framework is implemented in Python with modular components for generation, features, training, baselines, explainability, and evaluation. Experiments use Python 3.13 with NumPy, SciPy, pandas, scikit learn, XGBoost, SHAP, matplotlib, seaborn, and PyYAML. Configuration is centralized in YAML, and seed control is applied consistently for reproducibility. Recent wearable and reconfigurable entropy source studies \cite{b16}, \cite{b17} motivate this modular design because practical deployment often mixes hardware generation pipelines with software side validation.

\subsection{Data Split and Protocol}
Data is split stratified into train validation test partitions with 70/15/15 ratio, resulting in 700 train, 150 validation, and 150 test samples. All model selection and tuning decisions are based on validation behavior, while final numbers are reported on the held out test set.

The evaluation suite includes classification metrics, threshold independent ranking metrics, calibration analysis, per generator performance, and stress tests under distribution shift. This design aligns with recommendations that security oriented model assessment should move beyond single aggregate metrics and include reliability and subgroup behavior checks.

\subsection{Metrics}
We report accuracy, precision, recall, F1, ROC AUC, and weak class recall. F1 is computed as
\begin{equation}
F1 = \frac{2PR}{P+R}.
\end{equation}

Weak class recall is especially important for security use cases where missed weak generators can create high downstream risk.

\subsection{Stress Testing Design}
Stress tests examine model behavior beyond in distribution assumptions by evaluating an unseen algorithmic generator (Mersenne Twister), a pathological constant output stream, token length shifts (64 bit and 256 bit), and low sample regimes (10 and 50 tokens). These cases were selected to separate three effects: algorithmic mismatch, extreme deterministic failure, and statistical power degradation due to insufficient sample size.

This protocol is critical because many deployed systems violate ideal assumptions on batch size and data stationarity.

\subsection{Generalization Gap and Error Composition}
Validation to test transfer shows a measurable but consistent degradation, with AUC reductions largest for XGBoost and smaller for Random Forest and Logistic Regression. This indicates mild overfitting in a relatively small but high dimensional setting. Error composition from Fig.~\ref{fig:cm} shows that weak samples misclassified as strong dominate overall error for the top models, which is operationally significant because these are potentially risky false assurances.

Let $FP_w$ denote weak samples predicted as strong and $FN_s$ denote strong samples predicted as weak. In this task, minimizing $FP_w$ is often more security critical than maximizing aggregate accuracy. Future thresholding strategies can therefore optimize a weighted objective:
\begin{equation}
\mathcal{L}_{sec} = \alpha FP_w + \beta FN_s, \quad \alpha > \beta,
\end{equation}
to reflect deployment risk priorities.

This is coherent with expected statistical behavior and provides a valuable audit trail for individual decisions. In particular, false positive weak samples frequently show strong longest run and compression signals that overpower weaker counter evidence, suggesting a target area for future feature expansion.

\section{Discussion}
\subsection{Reliability and Calibration}
Probability quality matters in security triage. A model with acceptable classification accuracy but poorly calibrated confidence can mislead review workflows. RandFusion includes calibration analysis artifacts to inspect this behavior.

\begin{figure}[htbp]
\centerline{\maybegraphic[width=0.95\linewidth]{calibration_curves.png}}
\caption{Calibration behavior and confidence distribution.}
\label{fig:calib}
\end{figure}

As shown in Fig.~\ref{fig:calib}, confidence concentration is strongest near high probability regions for clearly separable cases, while borderline samples cluster in intermediate confidence bands. This pattern supports the use of confidence threshold policies for escalation, such as manual review for medium confidence outputs.

\subsection{Why Stacking Did Not Surpass Random Forest}
Stacking is beneficial when base learners make sufficiently diverse errors. In this dataset, Logistic Regression and Random Forest already share substantial agreement on easy and medium difficulty samples, while XGBoost contributes additional variance without enough complementary gain. The net effect is that stacking remains competitive but does not exceed Random Forest.

\subsection{Failure Mechanisms and Security Meaning}
The hardest classes are instructive. XOR collapse and predictable seed failures indicate that first order statistical descriptors can be satisfied even under insecure generation logic. Therefore, random looking output is not equivalent to cryptographic unpredictability. This mirrors security guidance that statistical evidence must be interpreted together with source design, seeding process, and threat model assumptions \cite{b2}, \cite{b7}, \cite{b9}. It also agrees with machine learning oriented randomness studies that warn against over interpreting test passing behavior without contextual analysis \cite{b5}, \cite{b6}, \cite{b11}.

\subsection{Practical Deployment Guidance}
For deployment as an audit aid, we recommend three controls. First, enforce minimum batch sizes to avoid low power statistical estimates. Second, keep token length consistent with training conditions or retrain with mixed lengths. Third, use confidence bands to trigger layered validation rather than hard accept reject automation.

\subsection{Threats to Validity}
\textbf{Construct validity:} Labels are generator family based and may not capture nuanced real world adversarial capability.

\textbf{External validity:} The training set includes controlled synthetic classes and may under represent production traffic patterns.

\textbf{Statistical validity:} Some stress scenarios sample fresh secure randomness, so exact confidence values vary across reruns.

\textbf{Method validity:} Current features emphasize classical tests and may miss higher order dependencies detectable by sequence models or richer batteries.

\section{Conclusion and Future Work}
RandFusion demonstrates that machine learning based fusion of classical randomness tests can improve decision consistency and ranking quality for cryptographic token evaluation. In the current benchmark, Random Forest provides the strongest balance across accuracy, F1, and AUC, while explainability artifacts support operational auditability.

The study also surfaces clear limits. Statistical features alone can miss classes whose insecurity is structural rather than first order statistical. Robust future systems should combine statistical fusion with context aware analysis, richer higher order tests, and expanded real world datasets.

Future work will therefore focus on five directions: broader weak generator families, mixed token length training, multi batch temporal analysis for seed predictability, calibration aware decision thresholds, and hybrid statistical plus sequence modeling pipelines.
